# Docs examples: gaps found by the Basic examples (#14)

Input for `docs/docs-examples-gaps.md`. Each row is a workaround an example needed.

| example | needed | workaround | proposed API |
|---|---|---|---|
| `focused-tab` | Style the selected tab of the **active** tabset differently from the other tabsets' selected tabs (gap 1). | `in-data-active:` and `not-in-data-active:` on the tab, reading the ancestor `TabSet`'s `data-active` (`[data-active] [data-selected]` in plain CSS). | `data-tabset-active` on `Dockable.Tab` (and `tabsetActive` in `TabState`). |
| `tabs-at-bottom` | Round the panel's corners on the side away from the strip (gap 2). | The example swaps the panel's `rounded-b-*` for `rounded-t-*` when the strip is at the bottom, repeating the tabset's radius. | `data-tabset` / tabset state on `Dockable.Panel`, or a panel layer the tabset can clip. |
| `close-tabs` | Render a hint inside an empty tabset's content area with `render={(props, state) => <div {...props}>…</div>}`. | `RenderedProps["ref"]` is `Ref<HTMLElement>`, which a `<div>` does not accept; the example narrows it with `ref={props.ref as Ref<HTMLDivElement>}`. | Type `RenderedProps` per primitive element (e.g. `RenderedProps<HTMLDivElement>` for div primitives) so spreading onto the default element type-checks. |
| `close-tabs` | Middle-click to close a tab. | `onAuxClick` on the tab (button 1) dispatching `Actions.deleteTab`; the kit's `KitTab` forwards no props, so a new `_kit/tab-strip.tsx` adds a prop-forwarding `KitTabButton`. | Optional: a `closeOnMiddleClick` behaviour (FlexLayout has it) or a documented recipe. |
| `add-tabs` | Dispatch actions from a toolbar **outside** `Dockable.Root`. | A child component calls `useDockable()` and hands the engine up through state (`EngineBridge`). | Expose the engine from the Root (`onEngine`/`engineRef` prop), or a `useLayoutEngine(model)` hook usable outside the Root. |
| `unstyled` | Show the layout with the stage theme off. | A wrapper with `all: initial` cuts inherited font/colour. The ide, paper and terminal theme files still style `[role="tab"]`, `[role="tablist"]` and `[data-active]` under the stage, so those rules reach the unstyled layout; the e2e runs in light and dark, which have no such rules. | Site-side: scope theme flourishes to kit-marked elements (e.g. `[data-tab-label]`, a `data-kit` attribute) so a theme never reaches markup that opted out. |
| (kit, seen in `unstyled` with the kit on, paper theme) | The splitter grip drawn along the splitter. | Kit bug, not worked around: `splitterGrip` uses `in-data-[orientation=…]:`, which also matches an enclosing `Dockable.Row`'s `data-orientation`, so a horizontal splitter inside a column gets the vertical grip too. | Kit fix: mark the splitter `group/splitter` and use `group-data-[orientation=vertical]/splitter:` / `group-data-[orientation=horizontal]/splitter:` in `splitterGrip`. |
