# Docs examples: gaps found by the Intermediate examples

Input for `docs/docs-examples-gaps.md` (Epic #10, issue #15). "Gap N" refers to section 2 of
`docs/walking-skeleton-report.md`. Every workaround below is also commented in the example's code.

| example | needed | workaround | proposed API |
|---|---|---|---|
| `locked-regions` | No drop indicator over a target that `setOnAllowDrop` (or `enableDrop`/`enableDivide`) refuses. | `DragDropManager.onDragOver` returns early when `findDropTargetNode` finds nothing, so the **last accepted indicator stays visible** (and `dropInfo` stays stale; the drop itself does not happen, since the browser gets no `preventDefault`). The example listens to `dragover` on the document (it arrives after the engine's root listener), reads `event.defaultPrevented`, and hides the indicator with a class on the root while the last `dragover` was refused. | On a `dragover` with no valid target, set the indicator to `visible: false` and clear `dropInfo`; expose the refusal as state (`refused`, `data-drop-refused` on `DropIndicator`/`Root`). Belongs with the Drop control Epic (#19). |
| `locked-regions` | Feedback for a refused drop beyond the cursor. | The browser's native "not allowed" cursor only (the engine does not `preventDefault`). A lock button with a Fragiola Tooltip explains the rule up front. | #19: a refusal reason from `onAllowDrop` and a refused-drop state on the target. |
| `drag-and-drop` | Highlight the tabset that is the drop target (gap 8). | Reads the core's indicator state (`engine.getDragDropManager().subscribe/getIndicatorState`), takes its rect's centre and finds the tabset whose `getRect()` contains it; the kit's `tabsetClassName` adds a ring. | `data-drop-target` (and `data-drop-location`) on the targeted `TabSet`, or `targetNodeId` in the indicator state. |
| `drag-and-drop` | Spread a `render` function's props onto a `<div>`. | `RenderedProps.ref` is `Ref<HTMLElement>`, which is not assignable to a `<div>`'s `Ref<HTMLDivElement>` (a `RefObject` is invariant), so the example casts `props as ComponentProps<"div">`. | Type the merged ref as `React.RefCallback<HTMLElement>` (assignable to any element's ref), or make `RenderedProps` generic over the element. |
| `scoped-palettes` | A panel in its tabset's palette (gap 2). | The panel lives outside the tabset, so the content repeats the palette read from the tabset's `config`. It goes on a content wrapper, not `panelClassName`: the kit's panel already has `palette-raised`, and an added `palette-surface` loses to it (the surface rules come first in the stylesheet). | Gap 2's `data-tabset` on `Panel`, plus the tabset node in `PanelState`, so `className={(state) => …}` can follow it. |
| `popout` | A pop out button, and a dock back button inside the window (gap 7). | The header button reads the selected tab's `isEnablePopout()` and `mainEngine.isSupportsPopout()`; in a window layout it moves the tab back with `mainEngine.doAction(Actions.moveNode(…))` into the main active (or first) tabset. | `Dockable.PopoutTrigger`, and an action that docks a window layout back (`Actions.closePopout` with the `"dock"` policy is close, but it closes the whole window). |
| `maximize` | Escape restores a maximized tabset. | A `keydown` listener on the engine's document (`engine.getCurrentDocument()`) dispatches `Actions.maximizeToggle`. | A `restoreMaximized` key in the keymap (default `Escape`), handled by `Root` like `focusNextTabset`. |
| `rename-tabs`, `tab-context-menu` | A text field inside a tab (inline rename). | The field stops key events from bubbling (the tab handles Enter, Space, arrows, Home, End and `Ctrl+Delete`, and prevents their default, so Space could not be typed), and the tab gets `draggable={false}` while editing. | `Tab` ignores keys whose target is an editable element (`input`, `textarea`, `contenteditable`) and does not start a drag from one; or a `Dockable.TabRename` part. |
| `overflow-select` | Know when a tab list overflows. | The consumer measures: a `ResizeObserver` on the tab list plus a check after every render compare `scrollWidth` with `clientWidth`. The list stays mounted and in the flow (only `invisible`), so the engine keeps measuring its strip and the measure cannot flicker. | `data-overflowing` on `TabList` (and in its state), from the strip measurements the engine already takes. |
| `undo-redo` | Names for the undo steps (a history list). | `onModelChange` mirrors the manager's own rule (not `isAdjusting()`, not an ignored type) to push a label; undo and redo move labels between two lists. | `UndoManager` keeps the action of each step: `getHistory(): { undo: Action[]; redo: Action[] }`. |
| `undo-redo` | Dispose the manager on unmount under StrictMode. | Not disposed: `dispose()` is final, and StrictMode's effect replay would dispose the instance its remount reuses. The manager is garbage-collected with its model. | A `useUndoManager(model, options)` hook in `@fragiola/dockable-react`, or a re-attachable `dispose`. |
| all with Fragiola popups (`tab-context-menu`, `overflow-select`, `scoped-palettes`, `component-factory`, `locked-regions`) | Menus, selects and tooltips in the example theme. | Fragiola popups portal into `document.body`, outside the themed stage. `_kit/stage-theme.ts` reads the stage's theme and puts `data-example-theme` on the popup (its box has `palette-raised`, and the theme rules match an element with both). Not a package gap: an app themes `<html>`/`<body>`. A menu opened from a tab in a popout window still portals into the main document. | Fragiola UI: a `container` prop on the `Content` wrappers (Base UI's `Portal` has one), which would also fix popout windows. |

Things that turned out **not** to be missing:

- status on a tab from its content: `Actions.updateNodeAttributes(tabId, { config })` + `getConfig()` + a consumer `data-*` on `Dockable.Tab` (arbitrary props are forwarded);
- a tab as a menu trigger: `render={<ContextMenu.Trigger />}` on `Dockable.Tab` works as is;
- drop rules: `model.setOnAllowDrop` plus `enableDrop`/`enableDrag`/`enableDivide` cover the centre, the sides, the strip and the layout edges;
- render on demand (`enableRenderOnDemand`, on by default) and a component factory from `getComponent()`/`getConfig()`;
- per-tabset palettes stored in the tabset's `config`.
