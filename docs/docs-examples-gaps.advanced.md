# Docs examples gaps: Advanced examples (#16)

What the four Advanced examples (`ide-workbench`, `analytics-dashboard`, `ops-monitor`,
`layout-lab`) had to work around. Each workaround is also commented in the example's code.

| example | needed | workaround | proposed API |
|---|---|---|---|
| ide-workbench, analytics-dashboard, layout-lab | Drive the layout from UI **outside** `Dockable.Root` (a file tree, a header of filters, a toolbar) through the engine, so `onAction` still sees the change. `useDockable()` only works inside the root, and `Root` exposes no engine; `model.doAction` skips `onAction`. | `_kit/engine-bridge.tsx`: an `EngineBridge` child of the root reports `useDockable().mainEngine` up through a callback; the example keeps it in state (it changes with the model). | An `engineRef` (or `onEngine`) prop on `Dockable.Root`, or a `Dockable.Provider` that can wrap siblings of the root. |
| ide-workbench | An empty state inside an empty tabset's content area. `TabSetContent` accepts no children (its props omit them). | `render={<div>{placeholder}</div>}` on `Dockable.TabSetContent` (the element's children are kept). | Document the pattern, or accept `children` on `TabSetContent` (rendered under the panels). |
| ide-workbench | Intercept every way a tab can close (button, context menu, Ctrl+Delete from the keymap) to ask about unsaved changes. | `onAction` vetoes `DELETE_TAB` for a dirty tab, queues it, and the dialog re-dispatches `Actions.deleteTab` with the id in a "confirmed" set. Works; the bypass set is boilerplate. | An async-friendly close hook (`onBeforeCloseTab(tab) => boolean \| Promise<boolean>`), or a documented "veto and re-dispatch" recipe. |
| ide-workbench, analytics-dashboard, ops-monitor | Content-aware tabs: the content reports a state (dirty, below target, alert level) that the tab shows. | The content writes it into the tab's `config` with `Actions.updateNodeAttributes` (only when it changes), and the tab reads `getConfig()` and sets a consumer `data-*` (`data-dirty`, `data-status`). The config replaces the whole object, so the content spreads the previous config. | A typed per-tab transient state that is not serialized (e.g. `tab.setState(key, value)` + `data-*`), or `updateNodeAttributes` merging `config` shallowly. |
| analytics-dashboard | A KPI writing its status must not create undo steps. | `UndoManager` with `ignoreActionTypes: [SET_ACTIVE_TABSET, UPDATE_NODE_ATTRIBUTES]`, which also ignores real attribute edits. | Let an action opt out of history (`action.setUserData({ undo: false })` honoured by `UndoManager`), or an `ignore(action) => boolean` option. |
| ops-monitor | Every service panel must report its status while hidden. | `tabEnableRenderOnDemand: false` globally, so all panels mount. | None needed; worth documenting next to content-aware tabs. |
| ops-monitor | Colour a status tab in themes that restyle the selected tab (terminal inverts it with the tab's own palette roles, so a palette class on the tab made the selected tab unreadable). | The tab surface stays the theme's; the status colours only the icon, a line and the badge (`data-status` drives them). | None in the package; a theme note: flourishes that recolour tabs should read a fixed palette, not the tab's. |
| all four | Menus, selects, tooltips and dialogs portal to `document.body`, outside the element carrying the example theme, so they take the page's colours. | `_kit/example-theme.tsx` `usePopupTheme(ref)` puts `data-example-theme` on the popup element (the themes also match it on the palette element itself). Tooltips also get `palette-surface`. | Site-only (the theme is scoped to the stage). A `container` prop on the vendored Fragiola `*.Content` parts would let examples portal into the stage. |
| ide-workbench | The examples browser lists an example's files by scanning `import … from "…"` in its sources, including text inside strings: demo file contents with import lines broke the manifest. | The demo files in `files.ts` have no import lines. | The scanner (`scripts/examples-lib.ts`) could use the TypeScript parser instead of a regex. |

Kit bug met on the way (fixed by the lead in `ab8ce6b`, cherry-picked): `useExampleTheme` read
the theme before a panel's content was attached, so `ChartPanel`s drew blank.
