title: Dockable.PopoutTrigger
description: A button that pops the selected tab, or the whole tabset, out into a window, and docks it back from the window.

"A button, inside `Dockable.TabSet`, that pops the selected tab (or the whole tabset) out into a
window, and, in a window, docks it back into the main layout. It renders nothing when neither is
possible (popouts unsupported, the model refuses it, no tab): `tab.popout` / `tabset.popout`
decide, through `model.can`. Its accessible name comes from `aria-label` or `getLabel`
(`Popout_Tab` / `Dock_To_Layout`)."

```tsx
<Dockable.TabSet node={tabset}>
    <div className="flex">
        <Dockable.TabList<Types>>{(tab) => <Dockable.Tab node={tab}>{tab.data.name}</Dockable.Tab>}</Dockable.TabList>
        <Dockable.PopoutTrigger aria-label="Pop out" className="data-[mode=dock]:rotate-180">
            <ExternalLinkIcon aria-hidden />
        </Dockable.PopoutTrigger>
    </div>
    <Dockable.TabSetContent />
</Dockable.TabSet>
```

## What a press runs

| mode | target | command |
| --- | --- | --- |
| `"popout"` | `"tab"` | `tab.popout` (`engine.popout(tabId)`): the tab moves into a new window layout, at its content area's screen rect |
| `"popout"` | `"tabset"` | `tabset.popout` (`engine.popout(tabsetId)`): the whole tabset moves into a new window layout |
| `"dock"` | either | `engine.dockBack(id)`: when the tab (or the tabset's tabs) is all its window holds, `window.close`, which docks every tab back and removes the window; otherwise a `batch` of `tab.move` into the main layout's active tabset (its first tabset when none is active) |

Every command goes through the model's middleware, so a veto stops it. A new window layout in the
state is what opens the native window: the root's popout manager opens one for every window layout
(see [Dockable.Popout](/docs/api/popout)).

## Props

`PopoutTriggerProps<T>` extends the [common primitive props](/docs/api/root#common-props) and the
`<button>` attributes.

| prop | type | default | description |
| --- | --- | --- | --- |
| `target` | `"tab" \| "tabset"` | `"tab"` | `"tab"` (default) pops out one tab; `"tabset"` pops out the whole tabset |
| `node` | `TabOf<T>` | the tabset's selected tab | the tab to act on; default: the enclosing tabset's selected tab |
| `children` | `ReactNode` | none | the button's content (an icon); the primitive renders no text of its own |

## State

`PopoutTriggerState`:

| field | type | description |
| --- | --- | --- |
| `mode` | `"popout" \| "dock"` | what a press does: open a window (`"popout"`) or dock back into the main layout (`"dock"`) |
| `target` | `"tab" \| "tabset"` | what it acts on: the selected tab (or `node`), or the whole tabset |

## Data attributes and ARIA

| attribute | value |
| --- | --- |
| `data-layout-path` | `<tabset path>/button/popout`, e.g. `/ts0/button/popout` |
| `data-mode` | `"popout"` or `"dock"` |
| `data-target` | `"tab"` or `"tabset"` |
| `aria-label` | from `getLabel`: `DockableLabel.Popout_Tab`, or `DockableLabel.Dock_To_Layout` in a window (your own `aria-label` wins) |
| `type` | `"button"` |

## Notes

- In the main layout it renders when `engine.canPopout(id)` is true: popouts are supported
  (`supportsPopout`) and `model.can("tab.popout", { tab })` (or `tabset.popout`) accepts it. The
  model refuses a tab whose resolved `enablePopout` is false (the built-in default: popout is
  opt-in, per tab or with `defaults.tab.enablePopout`), a pinned tab, and a tabset that is empty
  or holds a tab that does not allow it. A middleware veto hides it too.
- In a window (`engine.isInWindow(id)`) it always renders, in `"dock"` mode.
- The engine methods it calls are public: `engine.popout(id)` and `engine.dockBack(id)`, both
  returning a `CommandResult`. `model.run("tab.popout", { tab })` works as well, anywhere.
