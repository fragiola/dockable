title: The primitive contract
description: render (never asChild), className and style functions, structural style, ref and forwarded props.
---

Every primitive (`Dockable.Root`, `Row`, `TabSet`, `TabList`, `Tab`, `TabSetContent`, `Panel`,
`Splitter`, `DropIndicator`, `Popout`) follows the same rules. The package's tests enforce them.

## `render`, never `asChild`

A primitive renders a `div` by default. `render` replaces the element, Base UI style. There is no
`asChild`.

**An element**: its props are merged with the primitive's.

```tsx
<Dockable.TabSet node={tabset} render={<section />} />
```

**A function**: receives the props to spread and the primitive's state.

```tsx
<Dockable.TabSet
    node={tabset}
    render={(props, state) => <section {...props} aria-current={state.active ? "true" : undefined} />}
/>
```

The function form must spread `props` (they carry the ref, the ARIA, the `data-*`, the handlers
and the structural style). `props.ref` is a callback ref, so it fits any element's `ref`:
`render={(props) => <button {...props} />}` needs no cast.

## `className` and `style`: a value or a function of the state

```tsx
<Dockable.Tab
    node={tab}
    className={(state) => (state.selected ? "tab tab-selected" : "tab")}
    style={(state) => ({ opacity: state.dragging ? 0.4 : 1 })}
/>
```

Each primitive's state is documented on its [reference page](/docs/api/root). The same values
are on the element as `data-*` attributes, so a static `className` with attribute selectors is
usually simpler (see [State attributes](/docs/concepts/state-attributes)).

## Structural style wins

A primitive's only inline styles are **structural**: `position`, `inset`/`left`/`top`/`width`/
`height`, `display` (`flex`, or `none` to hide), flex sizing (`flex-direction`, `flex-basis`,
`flex-grow`, `min-*`/`max-*`), `overflow: hidden` on rows and tabsets, the splitter's preview
`transform`, and `pointer-events: none` on the drop indicator. Nothing cosmetic.

Your `style` is merged **under** the structural style: when both set the same key, the
primitive's value wins. On `Panel` the engine owns `position`, `inset`, `left`, `top`, `right`,
`bottom`, `width`, `height` and `display`, so those keys are dropped from your style entirely.

| primitive | structural style |
| --- | --- |
| `Root` | `position: relative` |
| `Row` | `display: flex`, `flex-direction`, `flex-basis: 0`, `flex-grow` (weight), `min-*`/`max-*`, `overflow: hidden`; the root row adds `position: absolute; inset: 0` |
| `TabSet` | `display: flex` (or `none` while another tabset is maximized), `flex-direction: column`, `flex-basis: 0`, `flex-grow` (weight), `min-*`/`max-*`, `overflow: hidden` |
| `TabList` | none |
| `Tab` | none |
| `TabSetContent` | `flex-grow: 1`, `flex-basis: 0`, `min-width: 0`, `min-height: 0` |
| `Panel` | `position: absolute`; the engine writes `left`, `top`, `width`, `height`, `display` |
| `Splitter` | `display: none` while a tabset is maximized; `transform` during an outline drag |
| `DropIndicator` | `position: absolute`, `left`, `top`, `width`, `height`, `display: none` when hidden, `pointer-events: none` |
| `Popout` (window root) | `position: absolute; inset: 0` |

## `ref` is a plain prop

React 19 style: `ref` is an ordinary prop, merged with the primitive's own ref (which registers
the element with the engine). Callback refs, object refs and inline functions all work.

```tsx
const tabsetRef = useRef<HTMLElement>(null);
<Dockable.TabSet node={tabset} ref={tabsetRef} />
```

## Props are forwarded, handlers compose

Anything else you pass lands on the element: `id`, `aria-*`, `data-*`, `title`, event handlers.
When the primitive has its own handler for the same event, **the internal one runs first, then
yours**:

```tsx
<Dockable.Tab
    node={tab}
    onKeyDown={(event) => {
        // runs after the tab's own key handling; check event.defaultPrevented
        if (event.key === "F2" && !event.defaultPrevented) startRename(tab);
    }}
    onContextMenu={(event) => openMenu(event, tab)}
/>
```

## No text

A primitive renders only its children. It never adds a label, a tooltip or an icon. Accessible
names come from you: see [Accessible names](/docs/getting-started/accessible-names).

## State only through `data-*` and ARIA

A primitive never adds a class name. Its state is on the element as `data-*` attributes (present
or absent, never `"false"`) and ARIA. The next page lists them all:
[State attributes](/docs/concepts/state-attributes).

## In Vue

`@fragiola/dockable-vue` follows the same contract with Vue's own means; the parts render the same
elements, attributes and structural style ([Vue primitives](/docs/api/vue)).

- **`as` and the `render` slot, never `asChild`.** `as` takes a tag or a component. The `render`
  scoped slot receives `{ props, state, children }`: bind `props` on your own element, and
  render the part's content with `<component :is="children" />`.

```vue
<Dockable.TabSet :node="tabset">
    <template #render="{ props, state, children }">
        <section v-bind="props" :aria-current="state.active ? 'true' : undefined">
            <component :is="children" />
        </section>
    </template>
</Dockable.TabSet>
```

- **`class` and `style` are fallthrough attributes**, merged under the structural style, as in
  React (on `Panel` the engine's keys are dropped). There is no function form: style the state
  with the `data-*` attributes, or with the `render` slot's `state`.
- **Listeners compose**: the part's own listener runs first, then yours (`@keydown`,
  `@pointerdown`, `@contextmenu`).
- **Recursion is slots**: the default scoped slot is the children function
  (`<Dockable.Row v-slot="{ node }">`, `<Dockable.TabList v-slot="{ tab }">`,
  `<Dockable.Panels v-slot="{ tab }">`), `#splitter="{ props }"` replaces `renderSplitter`, and
  `:splitter="false"` renders none.
- **A template ref on a part is its component instance**: its element is `$el`.
- **Vue never patches what the engine writes**: panels get their geometry from the engine after
  each render, and their content is teleported into the tab's moveable element, so moving a tab
  never remounts it.

## In Angular

`@fragiola/dockable-angular` follows the same contract with Angular's own means; the parts put the
same attributes and structural style on the same elements ([Angular directives](/docs/api/angular)).

- **The element is yours, never `asChild`.** Each primitive is an attribute directive on the
  element you write (`<section [dockableTabSet]="tabset">`): Angular's equivalent of `render`. Its
  state is a signal through `exportAs`.

```html
<section [dockableTabSet]="tabset" #part="dockableTabSet"
         [attr.aria-current]="part.state().active ? 'true' : null">
    …
</section>
```

- **Your `class` and `style` are untouched**: the directive adds only its structural keys, which
  win over a static `style` you write (on `[dockablePanel]` the engine writes the geometry). Style
  the state with the `data-*` attributes, or bind on `part.state()`.
- **Listeners compose**: the part's own listener runs first, then yours (`(keydown)`,
  `(pointerdown)`, `(contextmenu)`).
- **Recursion is template directives**: `<ng-template dockableRowChild let-node>`,
  `<ng-template dockableTabListItem let-tab>` and `<ng-template dockablePanels let-tab>` are the
  children functions, `<ng-template dockableRowSplitter>` replaces `renderSplitter`, and
  `[splitter]="false"` renders none. A nested row with no template renders with its parent's.
- **Angular never re-creates what the engine moves**: panels get their geometry from the engine
  after each render, and their content is moved into the tab's moveable element, so moving a tab
  never re-creates it.
