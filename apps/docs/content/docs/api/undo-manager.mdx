---
title: UndoManager
description: Undo and redo for a Model, collapsing gestures into single steps and preserving mounted content.
---

"Undo/redo for a `Model`. It owns the current model, records a snapshot before each model
mutation (collapsing an entire drag gesture into a single step), and replaces the model on
undo/redo via `Model.fromJson(json, current)` so mounted tab content is preserved."

```ts
const undo = new UndoManager(Model.fromJson(json));
const unsubscribe = undo.subscribe(() => render(undo.getSnapshot()));
undo.getModel()?.doAction(Actions.deleteTab("t1"));
undo.undo();
```

In React, see the [Undo and redo guide](/docs/guides/undo-redo).

## Constructor

`new UndoManager(model: Model | null, options?: IUndoOptions)`

`IUndoOptions`:

| option | type | default | description |
| --- | --- | --- | --- |
| `maxBufferSize` | `number` | `100` | maximum number of undo steps to retain |
| `ignoreActionTypes` | `string[]` | `[Actions.SET_ACTIVE_TABSET]` | action types that should not create an undo step |

## Members

| member | description |
| --- | --- |
| `getModel()` | the current model |
| `setModel(model, resetHistory = true)` | replaces the model (e.g. after loading a layout). By default the undo/redo history is cleared; pass `false` to keep it |
| `undo()` | undo the most recent change, if any |
| `redo()` | redo the most recently undone change, if any |
| `reset()` | clear the undo/redo history without replacing the model |
| `canUndo`, `canRedo` | true if there is at least one undo (redo) step available |
| `undoCount`, `redoCount` | the number of undo (redo) steps available |
| `getSnapshot()` | the current state; returns the same object until the state changes (bound, so it can be passed to `useSyncExternalStore` as is) |
| `subscribe(listener)` | calls `listener` whenever the snapshot changes; returns the unsubscribe function (bound) |
| `dispose()` | detaches from the model and drops every listener |

## Snapshot

`IUndoSnapshot`:

| field | type | description |
| --- | --- | --- |
| `model` | `Model \| null` | the current model |
| `canUndo` | `boolean` | true if there is at least one undo step available |
| `canRedo` | `boolean` | true if there is at least one redo step available |
| `undoCount` | `number` | the number of undo steps available |
| `redoCount` | `number` | the number of redo steps available |

## Behaviour

- Records through `model.addChangeListener`, so **every** action is recorded, whether dispatched
  with `engine.doAction` or `model.doAction`.
- Adjusting actions (a live splitter drag) record only the state before the first one: a whole
  gesture is one step. An ignored action in the middle of a gesture does not drop that snapshot.
- Undo and redo produce a **new** model instance: re-apply anything set on the instance
  (`setOnAllowDrop`, `setOnCreateTabSet`).
